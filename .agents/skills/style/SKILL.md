# Code Style

Follow the adjacent code and [AGENTS.md](../../../AGENTS.md). That file owns the binding invariants; read the relevant sections and module headers before changing handles, codecs, cancellation, or Android initialization.

## Keep domains together

The single Rust crate lives at `iroh4k/src/rust`. Each domain owns its shared logic and its C and JNI exports in one module. Keep infrastructure in the established shared modules rather than making private copies in each domain. Rust modules are private declarations in `lib.rs`, not a public glob re-export hierarchy.

For example, an endpoint operation normally touches:

| Layer | File under `iroh4k/src` |
| --- | --- |
| Rust logic and both exports | `rust/src/endpoint.rs` |
| Public API and internal expect declaration | `commonMain/kotlin/tech/annexflow/iroh4k/Endpoint.kt` |
| cinterop actual | `nativeMain/kotlin/tech/annexflow/iroh4k/Endpoint.native.kt` |
| JNI actual | `jniMain/kotlin/tech/annexflow/iroh4k/Endpoint.jni.kt` |

Prefix expect names with the domain. JNI actuals serve JVM and Android together; `androidMain` is for Android platform behavior. For a new domain, also register its Rust module and follow AGENTS.md's complete layout.

Keep related types and implementations together. Put Rust unit tests at the bottom of the module. Prefer existing functions and helpers over new abstraction layers; free functions are normal in this binding.

## Boundary code

Use narrow, explicit unsafe blocks where the FFI requires them, with the existing ownership and validity contracts. Caller-controlled values must produce errors rather than panics. Reuse the tagged Rust handles, shared Kotlin `NativeHandle`, and existing codecs and result envelopes. Keep error ordinals append-only.

For async changes, read [ops.rs](../../../iroh4k/src/rust/src/ops.rs) and [JniResult.kt](../../../iroh4k/src/jniMain/kotlin/tech/annexflow/iroh4k/JniResult.kt) before selecting result ownership and cancellation cleanup. Preserve both sides of handle cleanup and the established slot pattern where required. Preserve borrowed-future and watcher ownership patterns from AGENTS.md.

## Dependencies and generated files

Declare Rust dependencies in [the crate manifest](../../../iroh4k/src/rust/Cargo.toml); Kotlin dependency versions belong in [the version catalog](../../../gradle/libs.versions.toml). Preserve target-specific dependencies and existing TLS features. Dependency updates must follow AGENTS.md's version and toolchain checks.

The C header is generated by `build.rs` and cbindgen. Change exported Rust signatures rather than editing generated output. Check per-target cinterop linker options if a system dependency changes.

## Tests and documentation

A test should fail for a plausible behavioral defect, with expectations independent of the implementation. Stable contracts such as error ordinals and release versions legitimately need exact-value assertions.

Keep shared test bodies in `commonTest` and wire all three delegators. Preserve Android runner annotations and the documented pure-Kotlin decoder and Android-only exceptions. For network and leak assertions, use the hermetic setup, `Loopback.bounded`, and [LiveCounters.kt](../../../iroh4k/src/commonTest/kotlin/tech/annexflow/iroh4k/LiveCounters.kt); read their guidance before adding assertions. Keep test hooks internal.

Describe public behavior, lifetime, and cancellation in KDoc. Document implementation constraints where they explain a caller decision or protect an invariant. Use [prose](../prose/SKILL.md) for substantial guides and [check](../check/SKILL.md) for verification.
